# Predicting Respiratory Hospital Admissions from Air Quality: A Model Comparison

A data mining course project that tests how well daily hospital admissions can be predicted from air-quality and weather data across eight cities, and whether complex machine-learning models are worth their cost compared with simple ones.

> **Important: the dataset is synthetic.** Our data audit showed the data was generated by a program, not recorded in hospitals (for example, its dates run for 242 years with one row per day, and all eight cities have the same average pollution levels). The project therefore studies **how prediction models behave on a benchmark with a known structure**. **Nothing here is evidence about any real city or real health effect.**

## Description

Hospitals benefit from advance notice of busy days. Fine particulate matter (PM2.5) is one of the air pollutants most associated with breathing problems, so air-quality readings are a natural candidate for forecasting respiratory admissions. This project asks a practical question: **how accurately can daily hospital admissions be predicted from air quality, and does a more complex model earn its extra cost?**

We compare four model families, **Linear Regression, Decision Tree, Support Vector Machine (SVM) and Neural Network (MLP)**, on 88,489 city-days from eight cities. The same data is used in two ways: as a **regression** task (predict the number of admissions per day) and as a **classification** task (flag "spike" days, the busiest 10%). To make the comparison fair, every model is tuned with 5-fold cross-validation on identical folds; all preprocessing is fitted only on training data; 20% of the data is locked away and scored exactly once; and results are reported with bootstrap confidence intervals and a tie margin fixed before any results were seen.

Before modelling, we audited the dataset itself. The audit showed that the data has no real time structure, that every city looks statistically identical, and that only one input, PM2.5, is related to admissions. The project therefore evaluates the models on a controlled benchmark with a known signal-to-noise ratio, and the audit is itself one of the findings.

## Research questions

| ID | Question |
|---|---|
| RQ1 | Which model best predicts daily admissions? |
| RQ2 | Do cities differ? |
| RQ3 | Which inputs matter? |
| RQ4 | Can unusually busy ("spike") days be flagged in advance? |
| H1 | PM2.5 alone predicts about as well as all inputs. |

## Key findings

- **All four models perform the same**, explaining about 15% of day-to-day variation in admissions (R² ≈ 0.15), which is what one linear signal with correlation 0.39 allows. The SVM and neural network collapsed to the same straight line on PM2.5; the simple models match them while being faster and easier to explain.
- **PM2.5 is the only input that matters** (H1 supported). Models given only PM2.5 were as accurate as models given all eight features.
- **Cities share one relationship.** Separate per-city models were never better than one pooled model.
- **Spike days can be flagged, but weakly:** about twice as well as chance (PR-AUC 0.25 vs 0.12), but catching half of the spikes requires flagging about 28% of days.
- **The data is artificial:** admissions rise in exact steps of about +1 patient per 10 µg/m³ of PM2.5, whereas real effects are smooth. A Decision Tree captures these steps, which explains its very small edge.
- **Leakage-free evaluation:** scalers, encoders and thresholds were fitted only on training folds, and the test set was used once.

## Dataset

*Global Air Quality and Respiratory Health Outcomes* (Kaggle): https://www.kaggle.com/datasets/tfisthis/global-air-quality-and-respiratory-health-outcomes

- 88,489 rows, 12 columns, 8 cities (Delhi, Beijing, Mexico City, Los Angeles, London, Tokyo, Cairo, São Paulo), no missing values.
- **Inputs:** AQI (0–500 air-quality index), PM2.5 and PM10 (particles up to 2.5 and 10 micrometres, in µg/m³), NO₂ (nitrogen dioxide), O₃ (ground-level ozone), temperature, humidity and city.
- **Target:** `hospital_admissions`, daily patients admitted (0–25, mean 8.05).
- **Spike target:** a day with admissions ≥ 13, the 90th percentile of training data (11.7% of days).

## Methodology

1. **Audit first.** Validate the data and test its structure (dates, cities, correlations, shape of the PM2.5 effect).
2. **Split once.** 80% training (70,791 rows) and 20% test (17,698 rows), stratified by city and spike status. The test set is read only by the final evaluation script.
3. **Baselines.** "Always predict the mean" and "straight line on PM2.5 alone".
4. **Four models, tuned fairly** with 5-fold cross-validation on identical folds: Ridge/Logistic Regression, Decision Tree, SVM (RBF kernel) and a small MLP neural network (5 random seeds). Search sizes follow Bergstra & Bengio (2012).
5. **One final test**, with bootstrap 95% confidence intervals (1,000 resamples) and a tie rule set in advance: models differ only if the RMSE gap is ≥ 0.05 and the paired confidence interval excludes 0. A test R² above 0.20 would have triggered a leakage audit.
6. **Interpretation.** Permutation importance, partial dependence, linear coefficients and the tree's structure.

Random seed 42 throughout.

## Results

Test set (17,698 days, used once). RMSE is the typical prediction error in patients per day (lower is better); R² is the share of variation explained.

| Model | Test RMSE [95% CI] | R² |
|---|---|---|
| Mean predictor | 3.714 [3.675, 3.751] | 0.000 |
| Straight line on PM2.5 only | 3.419 [3.384, 3.460] | 0.152 |
| Linear Regression (Ridge) | 3.420 [3.384, 3.461] | 0.152 |
| Decision Tree | 3.409 [3.374, 3.449] | 0.157 |
| SVM | 3.420 [3.385, 3.462] | 0.152 |
| Neural network (5 seeds) | 3.425 [3.390, 3.466] | 0.150 |

Every model is inside the pre-set tie margin. The Decision Tree is detectably (but negligibly) better, because it follows the data's staircase shape. Spike classification (F1 ≈ 0.31 vs 0.21 for flagging every day) and per-city results are in [reports/RESULTS_SUMMARY.md](reports/RESULTS_SUMMARY.md).

## Limitations

- **Synthetic data:** no external validity. Results describe model behaviour on this benchmark, not real pollution or health.
- **Result largely follows from the data's design:** one linear signal plus noise leaves nothing for complex models to find. This should not be generalised to real data.
- **No time structure:** the dates are invalid, so a random split was used and no time-series models or lag features were possible.
- **Reduced scope:** repeated cross-validation, robustness checks, leave-one-city-out, Poisson regression, VIF, a real-data comparison and multiple-testing correction (Holm) were not done. City-difference p-values are unadjusted.
- **SVM:** trained on a 20,000-row subsample (justified by a flat learning curve from 5,000 to 40,000 rows). Its spike-alarm threshold transferred poorly because no probability calibration was used.
- **MLP classifier** stopped on training loss rather than validation loss (a scikit-learn limitation).
- **No pre-set margin for PR-AUC,** so very small gaps there are statistically detectable but practically negligible.
- **Post-test finding:** the staircase shape was discovered on training data after the test evaluation; no model was rebuilt and re-scored on the test set.
- **The audit described all rows,** including test rows, and the split-strata cutoff was computed on all rows. Both were descriptive or allocation-only; no model setting was chosen from them.
- **Small cities** (São Paulo, Cairo) have wide uncertainty.
